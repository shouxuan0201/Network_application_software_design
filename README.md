# 多人幾 A 幾 B 網路對戰系統

網路應用軟體設計期末專題，以 Python 實作支援 **BC/1.0** 通訊協定的多人猜數字遊戲。同一支 `bc.py` 透過子命令切換為伺服器、人類玩家客戶端或 AI 代理人，目標是讓不同組別的程式能跨網路互通。

本文件依據 [期末專題規範與 BC1.0 通訊協定](./期末專題規範與BC1.0通訊協定.pdf) 整理，操作方式已對照目前程式碼。協定細節與課程要求以原始 PDF 及課程勘誤公告為準。

> 目前儲存庫包含參考原型與協定自我測試工具。下列功能描述以現有程式為依據，不代表已通過全部驗收；完整測試結果、跨組互通紀錄及 AI 實驗數據仍需實際執行後補上。

## 1. 專案內容

```text
Network_application_software_design/
├── bc.py                          # server / client / ai 三種執行身分
├── bc_selftest.py                 # BC/1.0 協定自我測試工具，共 48 項檢查
├── README.md                      # 安裝、執行與操作說明
└── 期末專題規範與BC1.0通訊協定.pdf   # 課程規範與協定定義
```

執行伺服器後，預設在 `logs/` 產生每局的 JSON Lines 日誌。課程另要求根目錄包含 `requirements.txt`，目前尚未建立；現有兩支 Python 程式只使用標準函式庫，繳交前仍須補上此檔，可用註解註明無第三方依賴。

| 身分 | 子命令 | 主要工作 |
| --- | --- | --- |
| 伺服器（莊家） | `server` | 管理大廳、輪轉、回報、逾時、揭示驗證、名次與日誌，並可啟動 AI 子行程 |
| 人類玩家 | `client` | 輸入秘密與喊數、確認回報、觀看公開資訊；自動承諾與揭示 |
| AI 代理人 | `ai` | 自動完成所有玩家動作，利用公開回報更新候選集合與選擇喊數 |

所有玩家都主動以 TCP 連入伺服器，內建 AI 也走相同協定。莊家若要親自參賽，須另開終端機啟動 `client`。

## 2. 環境與安裝

- Python **3.10 以上**。
- 課程要求支援 Windows、macOS 與 Linux；目前各平台的完整驗證結果待補。
- 現有程式不需要安裝第三方套件。

先進入專案根目錄。Windows PowerShell 範例：

```powershell
cd "C:\Users\ASUS\Desktop\網應\Network_application_software_design"
python --version
python bc.py --help
```

可選擇建立虛擬環境，並直接使用其中的 Python，無須調整 PowerShell 執行原則：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe bc.py --help
```

以下命令均從專案根目錄執行。若使用虛擬環境，將 `python` 改為對應的執行檔；macOS／Linux 若以 `python3` 啟動 Python，請一併替換。

## 3. 快速開始

### 3.1 自動完成一局 AI 對戰

```powershell
python bc.py server --players 2 --bots 2
```

伺服器會啟動兩個 AI，玩家到齊後自動開局，結束後寫出日誌並退出。`--players` 是包含 AI 在內的玩家總數，`--bots` 是由伺服器自動啟動的 AI 數量。

### 3.2 一位人類與一位 AI

終端機 A 啟動伺服器：

```powershell
python bc.py server --players 2 --bots 1
```

終端機 B 加入遊戲：

```powershell
python bc.py client --host 127.0.0.1 --name G07-小明 --team G07
```

`G07` 為示例，跨組對玩時請換成本組代碼。

### 3.3 多人與跨組連線

主持端範例：

```powershell
python bc.py server --host 0.0.0.0 --port 5040 --players 4 --bots 1
```

其餘三位玩家分別以 `client` 或 `ai` 加入。下例的 `192.168.1.10` 須換成主持端實際可連入的位址：

```powershell
python bc.py client --host 192.168.1.10 --port 5040 --name G07-小明 --team G07
python bc.py ai --host 192.168.1.10 --port 5040 --name G08-AI --team G08
```

同局玩家名稱不可重複。到達指定人數即自動開局；若已有至少兩人，莊家可在伺服器終端機輸入 `start` 提早開局。此命令須在互動式終端機中使用。

### 3.4 連續主持多局

```powershell
python bc.py server --players 4 --bots 4 --games 10 --log-dir logs
```

`--games 0` 表示不限局數。每局結束後所有連線會關閉；下一局的人類玩家或外部 AI 須重新執行命令連線，伺服器自動啟動的 AI 則由伺服器重新建立。

## 4. 人類玩家操作

1. **等待開局**：連線後顯示大廳資訊，等待人數到齊或莊家輸入 `start`。
2. **設定秘密**：輸入四位互異的 ASCII 數字，例如 `0275`；直接按 Enter 可隨機產生。程式自動產生鹽值並送出承諾。
3. **輪到喊數**：依提示輸入四位互異數字，須在伺服器時限內完成。
4. **回報結果**：畫面顯示對方喊數、自身秘密與建議回報；按 Enter 採用建議值，也可輸入 `1A2B` 或 `1 2`。若修改成不符實際結果的值，程式會再次要求確認；不實回報可能導致取消資格。
5. **淘汰與終局**：收到揭示要求時自動送出秘密及鹽值。被猜中後不再喊數或回報，可繼續觀看至顯示最終名次。

客戶端以輸入執行緒搭配非同步網路接收，等待輸入期間仍可接收訊息。操作時應預留網路延遲，避免在時限最後一刻送出。

| 指令 | 用途 |
| --- | --- |
| `/say 文字` | 傳送聊天訊息，訊息長度上限為 200 字 |
| `/cands` | 顯示存活玩家的剩餘候選數量 |
| `/quit` | 送出離開訊息；對局中離開依協定處理 |

## 5. 遊戲規則與公平機制

- 每局 **2 至 6 人**。秘密及喊數皆為四位互異的 ASCII 數字，允許首位為 `0`，共有 5040 種；不同玩家可設定相同秘密。
- `A` 代表數字與位置皆正確，`B` 代表數字正確但位置錯誤。例如秘密 `0275`、喊數 `0927` 的結果為 `1A2B`。
- 合法回報須滿足 `0 ≤ A, B ≤ 4`、`A + B ≤ 4`，且不能為 `3A1B`。
- 每回合由一位存活玩家喊數，其餘存活玩家回報。伺服器收齊回報或逾時後一次公開；喊數者不回報自己的喊數。
- 回報 `4A0B` 者被猜中並淘汰。無論是否猜中任何人，都輪到下一位存活玩家。
- 存活人數不超過一人，或達到回合上限時進入終局。

承諾值計算方式如下，秘密與鹽值在揭示前留在客戶端：

```python
import hashlib
import secrets

salt = secrets.token_hex(16)
commit = hashlib.sha256(f"{secret}:{salt}".encode("ascii")).hexdigest()
```

鹽值為 32 個小寫十六進位字元，承諾值為 64 個小寫十六進位字元。伺服器逐回合檢查回報是否仍有相容的候選秘密，並在玩家被猜中或終局時驗證承諾及全部歷史回報；客戶端也會自行核對揭示結果。

| 終局狀態 | 名次規則 |
| --- | --- |
| `SURVIVOR` | 存活且驗證通過者列第一；因回合上限結束時可並列第一 |
| `GUESSED` | 排在存活者之後；被猜中的回合越晚，名次越前 |
| `FORFEIT` | 斷線、回報逾時或連續喊數逾時達上限；排在所有被猜中者之後，離場越晚越前 |
| `DQ` | 回報矛盾、揭示不符或未揭示等違規；取消名次，`rank` 為 `null` |

排名採標準競賽排名，例如 `1, 2, 2, 4`。承諾階段被移出的玩家不列入排名。

## 6. 命令列參數

### 6.1 伺服器

```text
python bc.py server [--host 0.0.0.0] [--port 5040] [--players 2] [--bots 0]
                    [--guess-timeout 60] [--feedback-timeout 60]
                    [--commit-timeout 30] [--reveal-timeout 15]
                    [--max-turns 120] [--max-skips 3]
                    [--games 1] [--log-dir logs]
```

| 選項 | 預設值 | 說明 |
| --- | --- | --- |
| `--host` | `0.0.0.0` | 監聽位址 |
| `--port` | `5040` | TCP 埠號 |
| `--players` | `2` | 總玩家數，範圍 2 至 6，包含 AI |
| `--bots` | `0` | 自動啟動的 AI 數量，範圍 0 至總玩家數 |
| `--guess-timeout` | `60` | 喊數時限，單位為秒 |
| `--feedback-timeout` | `60` | 回報時限，單位為秒 |
| `--commit-timeout` | `30` | 承諾時限，單位為秒 |
| `--reveal-timeout` | `15` | 揭示時限，單位為秒 |
| `--max-turns` | `120` | 每局回合上限 |
| `--max-skips` | `3` | 連續未喊數達此次數即棄權 |
| `--games` | `1` | 主持局數，`0` 為不限 |
| `--log-dir` | `logs` | 伺服器日誌目錄 |

各時限接受小數秒數，例如 `--guess-timeout 1.5`，應設定為正數。現有原型另提供 `--bot-cmd` 外部 AI 命令樣板選項，詳見 `python bc.py server --help`。

### 6.2 人類與 AI 客戶端

```text
python bc.py client --host HOST [--port 5040] --name NAME [--team G00]
python bc.py ai     --host HOST [--port 5040] --name NAME [--team G00] [--quiet]
```

`--host` 與 `--name` 必填。`--name`、`--team` 均為 1 至 20 字，不可含控制字元；同局名稱不可重複。`--quiet` 僅供 AI 減少畫面輸出。

## 7. BC/1.0 協定摘要

傳輸採 TCP，預設埠號 `5040`；每則訊息是 UTF-8、無 BOM 的單行 JSON 物件，以 LF 結尾，連同 LF 最多 **4096 位元組**。每個物件須包含字串欄位 `type`；不得送出 `NaN`、`Infinity` 或重複鍵。數字形式的秘密須以字串傳送，以保留首位的 `0`。

```text
LOBBY → COMMIT → PLAY → END → OVER
```

| 階段 | 主要訊息流程 |
| --- | --- |
| 大廳 | `HELLO` → `WELCOME`、`LOBBY`；連線後 10 秒內須完成合法 `HELLO` |
| 承諾 | `GAME_START` → `COMMIT` → `COMMITS` |
| 每回合 | `TURN` → `GUESS` → `GUESS_MADE` → `FEEDBACK` → `TURN_RESULT` |
| 淘汰或終局揭示 | `REVEAL_REQUEST` → `REVEAL` → `REVEALED` |
| 結束 | `GAME_OVER`，隨後關閉該局連線 |

完成 `HELLO` 後可穿插 `CHAT`、`PING`、`PONG`、`BYE`。收到 `PING` 須回應 `PONG`，若附有 `nonce` 則原樣帶回；接收端忽略未知欄位，客戶端忽略未知訊息類型。版本相容範圍為 `BC/1.x`。

錯誤以 `ERROR` 回覆。`fatal: false` 時可在原時限內修正重送；`fatal: true` 時連線關閉。同一連線累積超過 20 次錯誤會被斷線。各訊息欄位、錯誤優先序與斷線判定請參閱 PDF 第 8 至 16 節。

## 8. AI 策略

目前原型使用「最多劃分」（most-parts）基準策略：為每位對手維護候選集合，使用所有公開的 `TURN_RESULT` 刪去不相容數字，再鎖定候選最少的存活對手，優先選擇能產生較多種 A/B 結果的喊數。候選較多時會抽樣，以控制計算量。

課程要求設計報告包含至少 **100 局**對參考 AI 的實驗，呈現勝率、平均名次、平均回合數及統計誤差。目前尚未提供這些實驗結果；自我測試中的純 AI 對局不應直接當成對參考 AI 的效能實驗。

## 9. 測試與日誌

### 9.1 協定自我測試

完整執行 48 項檢查，並將逐項結果存成 JSON：

```powershell
python bc_selftest.py --server "python bc.py server" --json selftest-results.json
```

略過 50 局純 AI 對戰，執行其餘 38 項檢查：

```powershell
python bc_selftest.py --server "python bc.py server" --skip-bots --json selftest-quick-results.json
```

快速測試會將 10 項列為略過，不能視為全部通過。完整測試涵蓋 2 至 6 人純 AI 對戰各 10 局、連線與欄位錯誤、不實回報、揭示不符、斷線及各類逾時。

工具會自行啟動受測伺服器，預設自 `5600` 起選用可用埠號，約使用 15 個；可用 `--port` 更改起始值。測試日誌位於工具建立的暫存目錄，路徑會印在結尾並寫入 JSON 的 `logdir`。繳交前請保存完整終端機輸出及該目錄中的日誌。

**目前驗證狀態：**已核對程式的命令列說明；完整 48 項測試、跨組對玩及跨平台測試結果待補。

### 9.2 伺服器日誌

每局在 `--log-dir` 產生一個檔名含 `game_id` 的 `.jsonl` 檔，以 UTF-8 儲存。每筆收送訊息立即寫入並 flush，紀錄格式如下：

```json
{"ts":1791474054.218,"dir":"send","peer":"p1","msg":{"type":"TURN","turn_id":1,"guesser":"p3","alive":["p3","p2","p1"]}}
```

- `ts`：Unix 時間，單位為秒。
- `dir`：`send` 或 `recv`。
- `peer`：玩家 ID；完成 `HELLO` 前為 `IP:埠號`。
- `msg`：訊息物件，無法解析的輸入以 `{"raw":"…"}` 記錄。

伺服器日誌目錄只放每局日誌；測試結果 JSON、客戶端紀錄及其他證據請存放於其他位置。

## 10. 網路連線與常見問題

`0.0.0.0` 用於伺服器監聽，客戶端應填入伺服器實際 IP 或主機名稱。同機測試使用 `127.0.0.1`；跨機時須確認防火牆允許所選 TCP 埠號，跨網際網路則需要公開位址、埠轉發或可互通的覆蓋式 VPN。

Windows PowerShell 可測試 TCP 連通性：

```powershell
Test-NetConnection 192.168.1.10 -Port 5040
```

| 狀況 | 檢查方式 |
| --- | --- |
| 無法連線 | 確認伺服器正在執行、IP 與埠號一致，並檢查防火牆及路由設定 |
| 玩家到齊前一直等待 | 確認 `--players` 包含 AI；至少兩人時可在莊家終端機輸入 `start` |
| `NAME_TAKEN` | 換成同局未使用的玩家名稱 |
| `GAME_IN_PROGRESS` | 等待下一局開放大廳後重新連線 |
| 輸入被拒絕 | 使用四位互異的半形數字；不可輸入重複數字或全形數字 |
| 回報逾時或被取消資格 | 檢查操作時限、公開回報及揭示驗證結果，並保留日誌 |
| 中文顯示亂碼 | 確認終端機使用 UTF-8；可嘗試以 `python -X utf8 bc.py ...` 啟動 |

BC/1.0 使用明文 TCP，TLS 不在本版範圍內，聊天請勿傳送個人資料。
